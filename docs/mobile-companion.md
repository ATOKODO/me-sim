# Compagnon mobile local {#compagnon-mobile-local}

## Objectif et état {#objectif-et-etat}

Le compagnon PWA est un écran de saisie rapide pour les habitudes et les mesures. Le téléphone conserve les saisies en attente lorsque le PC est inaccessible. La base SQLite du PC reste la source de vérité : la synchronisation transfère ces saisies uniquement sur le réseau local, après appairage. Aucun compte, relais distant ou connecteur de santé n'est prévu pour cette version.

**État : fonctionnalité en cours de développement.** L'application Windows actuelle ne propose pas encore un parcours d'installation mobile validé de bout en bout. Cette page décrit le contrat à respecter ; elle ne garantit pas encore une installation sur iPhone ou Android.

Pour essayer cette version : dans **Préférences → Compagnon téléphone**, choisis le profil et active le service. Si Windows demande l'accès au réseau, autorise seulement les réseaux privés. Transfère le fichier public `companion-ca.crt` indiqué à l'écran vers le téléphone par un moyen local, puis compare le SHA-256 du **fichier reçu** avec l'empreinte affichée sur le PC avant de l'approuver. Ouvre ensuite l'adresse HTTPS affichée, saisis le code temporaire, puis installe la PWA depuis le navigateur. Les saisies enregistrées hors ligne se synchronisent à la prochaine ouverture de la PWA lorsque le PC redevient accessible. La configuration du certificat et l'installation varient selon le téléphone et doivent encore être vérifiées sur des appareils réels.

## Première installation et connexion {#premiere-installation-et-connexion}

La première ouverture doit avoir lieu lorsque le téléphone et le PC sont sur le même Wi-Fi et que le partage est activé dans Me-Sim. Le PC présente une adresse locale et un code d'appairage à usage limité. L'utilisateur associe le téléphone à un profil précis ; il peut ensuite retirer son accès depuis le PC. Le service local doit rester désactivé par défaut et n'écouter que sur le réseau choisi, avec une règle de pare-feu limitée au réseau privé.

Une PWA installable avec un service worker exige **HTTPS approuvé par le téléphone**. `http://localhost` n'est une exception que sur l'appareil qui ouvre la page : sur le téléphone, cette adresse désigne le téléphone, pas le PC. Un simple avertissement de certificat ignoré ne constitue pas un parcours de confiance fiable. Une installation sans cloud doit donc fournir un certificat local, afficher son empreinte sur le PC pour la comparer à celle du fichier reçu, expliquer comment l'approuver sur le téléphone, puis contrôler que le navigateur expose un contexte sécurisé avant l'installation. Sur iOS, un certificat racine ajouté manuellement demande aussi l'activation du _plein accès_ dans les réglages de confiance des certificats. Voir [MDN — installation PWA](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable), [MDN — service workers](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API) et [Apple — confiance d'un certificat installé](https://support.apple.com/en-us/102390).

L'adresse HTTPS doit rester stable : le navigateur isole les données par origine (protocole, nom et port). Si l'adresse IP ou le port change, la nouvelle adresse ne retrouvera pas automatiquement les saisies encore présentes sous l'ancienne. Cette version utilise l'adresse IP locale du PC ; une réservation d'adresse sur le routeur est donc recommandée. La prise en charge d'un nom local stable reste à développer. Aucun certificat ni secret privé ne doit être intégré aux fichiers publics de la PWA.

## Saisie hors ligne {#saisie-hors-ligne}

Après un premier chargement HTTPS réussi, le service worker conserve les fichiers nécessaires à l'ouverture hors ligne. Les saisies en attente vont dans IndexedDB sur le téléphone, avec un identifiant unique par opération, la date et l'heure locales choisies, l'instant de création en UTC et le profil associé. Cette version ne transmet pas de champ de fuseau horaire séparé. L'écran montre le nombre de saisies à envoyer et la date de dernière synchronisation confirmée. Une saisie n'est retirée de la file qu'après accusé de réception durable par le PC ; une nouvelle tentative transmet le même identifiant afin d'éviter les doublons. L'application retente la synchronisation après chaque saisie, à l'ouverture, au retour du réseau, lorsqu'elle redevient visible et toutes les 30 secondes tant qu'elle reste ouverte avec des saisies en attente ; un bouton manuel est aussi disponible. Une application fermée ne peut pas promettre une synchronisation en arrière-plan, particulièrement sur iOS.

Ces données existent **sur le téléphone jusqu'à leur transfert**. IndexedDB appartient au stockage du navigateur, qui peut être effacé par l'utilisateur ou évincé selon l'appareil ; demander un stockage persistant réduit certains risques sans garantir une sauvegarde. Le mode privé n'est pas adapté. L'interface doit signaler un échec d'écriture et éviter d'annoncer une saisie comme enregistrée avant la fin de sa transaction locale. Voir [MDN — IndexedDB](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API/Using_IndexedDB) et [MDN — quotas et éviction](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria).

Dans cette première version, la file et le jeton d'appairage ne sont pas chiffrés par Me-Sim sur le téléphone. Le verrouillage de l'appareil et les protections de stockage du navigateur sont donc nécessaires pour empêcher un tiers ayant accès au téléphone de les lire. La clé privée de l'autorité de certification locale doit rester exclusivement sur le PC ; seul son certificat public peut être copié vers le téléphone.

## Synchronisation et conflits {#synchronisation-et-conflits}

Le téléphone n'accède ni à SQLite ni aux fichiers du PC. Il envoie des opérations typées à un service local du processus Windows, qui vérifie l'appareil, le profil, les valeurs et les limites de taille avant une écriture transactionnelle. Le PC renvoie les identifiants acceptés, en conflit ou rejetés. Une opération déjà appliquée avec le même identifiant reçoit de nouveau un accusé `accepté`, ce qui rend les nouvelles tentatives sûres. Une réponse différente pour la même habitude et la même date, ou une mesure différente au même moment, reste en conflit sans remplacement silencieux. La correction d'une coche déjà synchronisée se fait sur le PC dans cette première version. La révocation d'un appareil bloque ses prochaines synchronisations, sans effacer automatiquement les saisies encore présentes sur ce téléphone.

Le partage fonctionne seulement quand le PC est allumé, que Me-Sim autorise la connexion et que les deux appareils peuvent se joindre sur le réseau local. Certains Wi-Fi invités isolent les appareils entre eux. Aucun accès à distance, relais, DNS public ni service cloud n'est requis. Un test réel sur iPhone et Android, réseau coupé puis rétabli, fait partie de la validation avant de déclarer cette fonction prête.

## Vérifications avant livraison {#verifications-avant-livraison}

Le parcours doit être exercé sur de vrais téléphones Android et iOS : première installation avec certificat approuvé ; saisie en mode avion puis redémarrage de la PWA ; retour au Wi-Fi et synchronisation unique malgré plusieurs tentatives ; conflit conservé et visible ; révocation d'un téléphone ; PC éteint ou Wi-Fi invité isolé ; changement d'adresse locale avec des saisies encore en attente. Ces vérifications restent à réaliser avant d'annoncer la fonction comme prête.
