## Initial verdict {#verdict-initial}

The foundation works and supports a convincing demonstration of the local journal, calendar and avatar. I do not yet recommend a stable release. Fix the defects below and verify installers matching the delivered revision. The full V1 of the original plan remains unfinished because scientific simulation is not enabled.

The review changed no application code or personal data. Reproductions use fictional profiles, temporary SQLite databases and a simulated Tauri transport for screens. Production Rust modules are reused directly in reproduction probes.

## Confirmed defects {#defauts-confirmes}

<!-- prettier-ignore -->
### 1. P1 — a stale view can overwrite another instance's changes {#_1-p1-—-une-vue-ancienne-peut-ecraser-les-changements-d-une-autre-instance}

Locations: `src-tauri/src/lib.rs:35–40`, `src-tauri/src/domain.rs:479–481`, `src-tauri/src/store.rs:67–81`.

The command reloads the database before applying a mutation containing a full profile from the UI. This updates the local revision, so `replace` cannot detect that the submitted profile was read before another instance changed it. No single-process restriction is implemented.

Confirmed with two connections to one file: A keeps the original profile; B saves a 12,000-step Target; A renames the profile from its stale view. Reproducing `load → mutate → replace` makes A's save succeed and remove B's Target. The existing concurrency test covers two stale snapshots sent directly to `replace`, not this actual path.

Fix: carry the expected revision from the user's read through the command and reject stale mutations before application; refresh without losing drafts. Mutations limited to changed fields also reduce overwrites. Alternatively, explicitly restrict the initial release to one instance.

<!-- prettier-ignore -->
### 2. P2 — the daily summary mixes old measurements and unknown data {#_2-p2-—-le-recap-quotidien-melange-anciennes-mesures-et-donnees-inconnues}

Locations: `src/app/core/store.ts:62–89`, `src/app/pages/dashboard.ts:300–371`.

`daily("activity")` uses the latest measurement regardless of date. Missing event aggregates become zero. A 90-minute activity measurement dated 20 September appears in the 1 October summary without recent activity. Without tobacco/alcohol observations, the screen displays `0 cigarettes` and `0 glasses`.

This contradicts the plan's principle that absent data stays unknown. Sleep already displays a dash when missing; other metrics need a similarly explicit rule.

Fix: define the summary period, filter all its measurements to it, retain absence and distinguish reported zero from missing input. Define how Total activity relates to exercise/walking to avoid counting minutes twice.

<!-- prettier-ignore -->
### 3. P2 — the calendar and time windows do not follow the clock {#_3-p2-—-le-calendrier-et-les-fenetres-temporelles-ne-suivent-pas-l-horloge}

Locations: `src/app/pages/habits.ts:412–415`, `src/app/core/store.ts:48–59` and `src/app/core/store.ts:103–106`.

`todayKey` is calculated once when the page is created. `Date.now()` and `new Date()` are not reactive Signal dependencies; computed values stay cached until data changes.

Playwright-clock reproductions confirm that after 1 October becomes 2 October, Habits stays on the first and the second's button remains disabled. Yesterday's 12:01 event stays in the timeline after 12:32 the next day, even though its end is older than 24 hours.

Fix: introduce a shared reactive local clock, refresh on day changes and foreground return, and make calendar, trajectories and timeline depend on it. Retain deliberately selected dates.

<!-- prettier-ignore -->
### 4. P2 — Excel times become dates {#_4-p2-—-les-heures-excel-sont-transformees-en-dates}

Location: `src-tauri/src/exchange.rs:105–112`.

The reader converts every date/time cell with `d.date().to_string()`. A native Excel `hh:mm` cell containing 18:30 becomes `1899-12-31`. Mapping it as a time makes HH:mm validation reject it. Text times work, hiding the defect in simple cases.

Confirmed with a generated XLSX containing an ISO date, duration 30 and native Excel time 18:30: preview reports an error.

Fix: retain cell types until mapping, then normalize dates, times and durations separately. Add reference cases with native Excel times and combined date/time cells for supported formats.

<!-- prettier-ignore -->
### 5. P2 — tobacco import does not offer its fixed unit {#_5-p2-—-l-import-de-tabac-ne-propose-pas-son-unite-fixe}

Location: `src/app/pages/data.ts:475`.

The backend expects `cigarette`, but the wizard only offers kg, lb, g, h, min, pas, kcal, kJ, /10 and verre. A two-column date/value tobacco file cannot be imported through the UI without adding a unit column. A file already containing that unit works.

Fix: offer all supported units, including `cigarette`, and derive choices from the metric catalogue to prevent divergence.

<!-- prettier-ignore -->
### 6. P2 — the form accepts values rejected by Windows {#_6-p2-—-le-formulaire-accepte-des-valeurs-refusees-par-windows}

Locations: `src/app/pages/journal.ts:330–336`, `src/app/pages/journal.ts:392–396`, `src-tauri/src/domain.rs:304–307`.

For vaping and other minute-based events, the form accepts zero and enables saving. It sends zero duration, which Rust rejects with `INVALID_DATA`. Simulated transport confirms the payload; Rust validation confirms rejection. Browser preview accepts it and hides the native issue.

Integers also need consistent validation: cigarettes are integers in Rust, while journal input uses a 0.1 step without an integer validator.

Fix: define how to save zero without creating a zero-duration animation, and apply the same rules in the form/backend. Check the no-vaping-today flow.

## Features and checks still needed {#fonctionnalites-et-verifications-encore-necessaires}

- **Science**: implement the complete model, confirm rights/domain, document inputs and reproduce independent references before enabling horizons. Current disabling is correct; determinism tests do not establish this validation. See `docs/model-card.md`.
- **Tracking continuity**: Yes/No calendar and quantitative journal are separate inputs. Checking I smoked creates no event or animation; adding a cigarette in the journal does not fill the calendar. This is documented, but integrated daily input would better match the requested experience. Custom habits without a metric have no dedicated animated event.
- **Deviation explanation**: one matching sleep observation can produce 0% while twelve dimensions are unknown. Show coverage next to the score. Normalization also uses one threshold of 60 for minutes, glasses and cigarettes; define visible per-metric scales. This is a personal indicator, not a scientific projection.
- **Data control**: profile deletion removes its active database rows as stated in the dialog/README. Preventive backup management and explicitly scoped workspace purging are missing. Do not call it forensic erasure or implicitly remove user-chosen exports elsewhere.
- **Windows delivery**: files in `release/` predate camera and translation/theme commits and do not represent HEAD. Rebuild packages identifiable by version/revision; test the offline package in a clean Windows VM without network, including WebView2. Offline configuration exists but CI builds only the standard package. Signing and clean installation checks remain to be arranged.
- **Performance**: measure comparison rendering on reference hardware and GPU resources after prolonged route changes. Limiting the loop to roughly 30 fps does not prove that target is achieved there.

Application encryption and mobile synchronization are not defects of this V1: the plan chose an unencrypted local database and deferred mobile apps. Remote connections need their own scope and tests if added.

## Useful refactoring {#refactorings-utiles}

1. Replace full-profile saves with targeted revision-checked commands. Reserve `Store::replace`, which deletes and reinserts all tables, for restoration; use targeted SQL transactions for ordinary input. A Yes/No answer or theme change currently rewrites every profile's data.
2. Centralize metrics, units, limits, integer constraints and animation modes in a shared/verified TypeScript–Rust contract. Tobacco and zero-duration divergences show the need.
3. Extract summary/deviation into pure functions with explicit dates, coverage and testable aggregation rules. Add a reactive clock service for components.
4. Add tests of real commands alongside internal SQLite tests and simulated transport. Target the six reproductions and native import/export dialogs.
5. Align habit limits: Rust counts archived habits among 100 permitted, while the UI counts only active ones. Repeated removals/additions eventually block a profile despite an enabled button.

Scene isolation, the local clip manifest, one-model-per-file cache and resource release are useful artist boundaries; a general rewrite is unnecessary to fix these defects.
